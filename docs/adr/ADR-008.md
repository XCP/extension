# ADR-008: Storage error handling pattern

No standalone record of this decision survives. The code cites it by number, and this page collects
only what those citations state. It adds nothing to them.

- **Writes must throw.** A storage write that cannot complete, including when the session storage
  API is unavailable, throws rather than failing silently
  ([`sessionMetadataStorage.ts`](../../src/platform/storage/sessionMetadataStorage.ts):
  "per ADR-008: writes must throw"; [`requestStorage.ts`](../../src/platform/storage/requestStorage.ts):
  `store`, `remove` and `clear` "throw if session storage API is unavailable (per ADR-008)").
- **Service state persistence follows the same rule.**
  [`BaseService.test.ts`](../../src/services/core/__tests__/BaseService.test.ts) asserts that a
  failed state save throws: "SET operations throw on error".

The read side in the same modules returns an empty value (`null` or `[]`) when storage is
unavailable or holds invalid data, except that a read taken in order to write fails rather than
returning empty: "A failed read is never evidence that it is safe to overwrite the store"
(`requestStorage.ts`).
